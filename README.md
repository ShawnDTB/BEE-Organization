# BEE Organization

**A brand, commerce, and operations platform for BEE Organization LLC.**

BEE Organization is an early-stage custom apparel and embroidery business being built from the ground up. The company is currently acquiring equipment, establishing its production process, defining its public identity, and preparing for its first official customer sale.

This repository contains more than a website. It is the beginning of the connected digital foundation that will support how BEE Organization presents its work, captures opportunities, manages customer projects, earns trust, and turns first-time orders into recurring relationships.

> **Project status: Pre-launch / early business development**
>
> BEE Organization has not yet completed its first official sale. The website and the business are being developed together so the systems needed for long-term growth exist before demand begins to scale.

## The objective

The immediate milestone is the first customer. The larger objective is to build a business customers return to.

BEE Organization is being positioned to serve:

- Schools, teams, clubs, and community organizations
- Businesses needing uniforms or branded apparel
- Events and groups placing coordinated or bulk orders
- Streamers, content creators, and online communities
- Individuals requesting custom apparel or personalized pieces

Success is not defined by launching a polished website or completing one transaction. Success means creating a dependable experience that supports initial inquiries, clear quoting, production communication, reorders, referrals, seasonal programs, merchandise refreshes, and long-term customer partnerships.

## Built with the DTB philosophy

This project is being developed with **Designed to Breakthrough LLC (DTB)** as a long-term digital systems partner.

The DTB philosophy is that a growing business does not need a collection of disconnected technology projects. It needs one connected foundation that helps the company look professional, capture leads, stay organized, retain control of its information, and improve as the business grows.

For BEE Organization, that means the website should become the public entry point to a larger operating system:

```text
Brand and service experience
            ↓
Quote requests and artwork intake
            ↓
Customer, project, and approval records
            ↓
Production communication and order status
            ↓
Delivery, follow-up, reorders, and referrals
            ↓
Analytics that guide future improvements
```

The platform should create value that remains inside the business. Processes should be documented, information should be structured, access and ownership should be clear, and future tools should strengthen the same foundation instead of creating additional silos.

## Guiding principles

### Honest before impressive

The platform must never manufacture credibility. Until BEE Organization has real customer work, reviews, order history, production data, and proven turnaround expectations, the website will communicate its current stage truthfully.

Being new does not require looking temporary or unprepared. Professionalism should come from clarity, thoughtful systems, responsive communication, strong samples, and a reliable customer experience—not inflated claims.

### A digital headquarters, not a brochure

The public website is only the first layer. The long-term platform should connect marketing, lead capture, customer intake, artwork, proofs, payments, order records, communication, analytics, and reorders wherever those systems provide meaningful operational value.

### Designed for the second order

The first sale validates the offer. The second sale begins to validate the business.

Every customer-facing and operational decision should reduce friction for future work by preserving approved designs, project context, garment details, decoration methods, quantities, communication history, and reorder information where appropriate.

### Professional presence and local trust

The website should make BEE Organization easy to understand, easy to contact, and safe to begin a project with. Visitors should know what the company can currently provide, what information is needed for an estimate, what happens next, and where expectations still require direct confirmation.

### Operational control

BEE Organization should not become dependent on undocumented workflows, scattered files, private accounts, or knowledge held by only one person. The project should favor centralized configuration, documented processes, controlled access, reliable storage, and clear responsibility.

### Scalable without pretending to be large

The platform should work for the business BEE Organization is today while leaving room for the business it may become. Features should be introduced when operations can support them—not simply because they make the website appear more advanced.

### Improvements that compound

Completed projects should strengthen the portfolio. Customer questions should improve the content. Order history should improve quoting and reorders. Analytics should improve conversion. Operational lessons should improve documentation. Each stage should leave the company with a stronger system than it had before.

## Current business stage

BEE Organization is presently working through the foundation phase:

- Initial equipment acquisition and production setup
- Testing materials, decoration methods, and repeatable workflows
- Defining service boundaries and production capabilities
- Developing samples and a legitimate starting portfolio
- Establishing pricing logic and quote factors
- Planning customer communication and approval procedures

## Customer journey being designed

The intended customer experience is structured around clarity and continuity:

1. **Discover** — Understand BEE Organization, its current services, and whether the project is a fit.
2. **Start** — Submit project goals, quantities, garment needs, artwork status, timing, and contact information.
3. **Clarify** — Review requirements, production feasibility, pricing factors, and expectations.
4. **Approve** — Confirm garments, artwork, placement, proofs, quantities, pricing, and terms.
5. **Produce** — Maintain organized production records and clear customer communication.
6. **Deliver** — Complete fulfillment with documented project details.
7. **Follow up** — Request authentic feedback, identify future needs, and make reordering easier.
8. **Grow together** — Support restocks, seasonal apparel, new team members, events, campaigns, or additional collections.

## Content and trust standards

The current build intentionally avoids:

- Private personal names in public project documentation
- Unapproved customer names, schools, organizations, or creator identities
- Invented testimonials, order counts, savings claims, partnerships, or experience
- Guaranteed turnaround without sufficient production data
- Public flat pricing that ignores garment, quantity, artwork, decoration, and fulfillment variables
- Presenting sample work as completed customer work
- Presenting placeholder branding as final
- Promising services or production methods before they are operationally confirmed

Real work, real feedback, real production data, and approved customer stories will replace placeholders as the business earns them.

## Platform roadmap

### Phase 1 — Foundation and first sale

- Finalize the initial service boundaries
- Confirm production-ready equipment and methods
- Build legitimate samples and product photography
- Complete the quote and artwork-intake workflow
- Establish proof, approval, payment, and production procedures
- Prepare the website for the first qualified customer

### Phase 2 — Learn from real orders

- Add approved customer projects to the portfolio
- Collect authentic feedback and testimonials
- Document common quote factors and customer questions
- Measure inquiry quality and conversion barriers
- Refine production estimates using actual order data
- Improve communication templates and internal checklists

### Phase 3 — Make repeat business easier

- Preserve customer and project records
- Support secure artwork uploads and proof approvals
- Create practical reorder workflows
- Add follow-up, referral, and repeat-customer campaigns
- Develop organization-specific programs where demand supports them
- Improve analytics across inquiry, quote, sale, and reorder stages

### Phase 4 — Scale the operating system

- Add deposits and online payment collection where appropriate
- Introduce order status and customer notifications
- Evaluate customer accounts and saved designs
- Support private or organization-specific storefronts
- Add inventory or supplier integrations only when operationally justified
- Expand reporting, permissions, backups, security, and documented ownership

## Measures of progress

The project should be evaluated by real business outcomes, including:

- Qualified inquiries received
- Quotes completed and accepted
- First official sale
- Projects delivered successfully
- Customers who place another order
- Referrals generated by completed work
- Time required to quote, approve, and manage an order
- Accuracy of production expectations
- Growth of the approved portfolio
- Increasing operational clarity and control

Traffic and visual polish matter, but they are not substitutes for trust, conversion, delivery quality, or retention.

## Technology

- React 19
- TypeScript 6
- Vite 7
- Cloudflare Pages-compatible routing
- GitHub Actions for automated installation, type checking, and production build validation

### Requirements

- Node.js 20.19 or newer
- npm 10 or newer

Node.js 22.16.0 is pinned through `.node-version` and used by CI.

### Local development

```bash
npm install
npm run dev
```

The development server normally runs at `http://localhost:5173`.

### Production validation

```bash
npm run check
```

This runs TypeScript validation and the Vite production build.

### Repair an older failed Windows installation

```cmd
rmdir /s /q node_modules 2>nul
if exist package-lock.json del package-lock.json
npm cache verify
npm install
npm run dev
```

The original dependency set referenced an unavailable React type release, causing installation to stop before the project-local Vite executable was installed. The dependency versions are now compatible, and GitHub Actions validates installation and production compilation.
